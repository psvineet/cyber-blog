After Hours - 7th August

The After Hours challenge involves analyzing forensic artifacts from a system compromised by persistent, hidden malware. The attacker bypassed standard autostart locations (like Registry Run keys or Scheduled Tasks) by abusing custom WMI (Windows Management Instrumentation) properties to hide an obfuscated fileless binary that creates a backdoor account.

Technical Breakdown & Key Findings

  • Hidden Storage in System Repository (WMI Abuse): Instead of saving files to the hard drive or using standard auto-run registry keys, the attacker stored the hidden program inside a custom, fake system setting (Win32_HardwareTelemetry) within the Windows management database.

  • In-Memory Execution (Fileless Malware): The initial script used PowerShell to pull the hidden code directly into the computer's memory (RAM) and run it without creating a file on disk. This effectively bypassed traditional antivirus software that scans files on the hard drive.

  • Target Checking (Evasion Technique): Before executing, the malware checked if the computer's name matched bytelotusdc. If it was running on any other machine (like a cybersecurity analysis lab or automated sandbox), it immediately closed itself to avoid detection.

Recommended Remediation Steps

  • Remove Unauthorized Backdoor Account: Delete the rogue user account created by the attack by executing:

    DOS

    net user patch /delete
    net user patch /delete

  • Clean Up the System Repository: Completely wipe the fake system class used to store the payload by running:

    PowerShell

    Get-WmiObject -Namespace "root\cimv2" -Class "Win32_HardwareTelemetry" | Remove-WmiObject
    Get-WmiObject -Namespace "root\cimv2" -Class "Win32_HardwareTelemetry" | Remove-WmiObject

  • Strengthen System Defenses (Hardening):

    • Restrict Rights: Prevent standard, non-administrator users from creating or modifying custom database entries in Windows Management Instrumentation (WMI).

    • Lock Down PowerShell: Turn on PowerShell Constrained Language Mode (CLM) to prevent unauthorized scripts from loading external code directly into memory.

    • Enable Security Auditing: Activate PowerShell Script Block Logging (Event ID 4104) so security teams can monitor and record the actual code run inside hidden script commands.
